# Draft clearing, Dock presence, and simple install — Design

Date: 2026-10-14 · Branch: `fix/draft-and-install` · Decisions agreed in a grilling session with the user.

## Goals

1. Sending a message empties the message box immediately.
2. A normal Mac user can install Pet Chat without Terminal or Xcode.
3. Pet Chat shows in the Dock (by default) so people can see it is running.

Non-goals: Developer ID signing / notarization, auto-updates, Homebrew cask, Mac App Store, custom DMG background, a professionally designed icon. (Revisit signing, Sparkle and Homebrew once there is an Apple Developer account.)

## 1. Draft clears on send

Terms: **Draft** and **Turn** as defined in `CONTEXT.md`.

- On send, the Draft (text + attached images) is emptied immediately, before the provider is contacted.
- **Failure before the Turn is recorded** (provider unreachable, model missing, images unsupported, attachment load failure, Stop during model discovery): the sent text and images return to the Draft — but only if the Draft is still empty; if the user has started a new Draft, it is left untouched and only the error shows. Attachment files must not be deleted while they are out of the Draft.
- **Failure after the Turn is recorded** (stream breaks, incomplete response): the Draft stays empty. The error bar's Retry re-asks that Turn in place (the existing regenerate-last-reply path), so the message is not duplicated.
- Stop after the Turn is recorded: Draft stays empty; the stopped reply shows "Stopped" and can be retried from its Retry action.
- App relaunch with a failed last Turn: no longer copies the question back into the Draft; the error bar offers Retry, which re-asks the Turn in place.
- "Tell me more" and suggestion chips follow the same rules (their text never lingers in the box).
- Tests: unit tests on AppModel for each case above (immediate clear; pre-record failure restores; restore skipped when a new Draft exists; post-record failure leaves Draft empty and Retry regenerates; relaunch behaviour). Update the UI test that expects the draft to persist, and add one asserting the box is empty right after Return.

## 2. Dock presence

- Default: Pet Chat is a regular app — Dock icon, Cmd+Tab entry, and a top-bar app menu with **Settings…** (Cmd+,) and **Quit Pet Chat** (Cmd+Q).
- Clicking the Dock icon opens the chat panel, re-showing the pet first if it was hidden.
- The menu-bar cat stays, unchanged.
- New setting **Show in Dock** (Settings, on by default). Off = today's behaviour (no Dock icon, not in Cmd+Tab). Takes effect immediately, no relaunch.
- Remove `INFOPLIST_KEY_LSUIElement = YES`; the activation policy is set at launch from the setting.
- Tests: unit test that the setting maps to the right activation policy and persists; existing panel/UI tests keep passing.

## 3. App icon

- New asset catalog `PetChat/Assets.xcassets` with an `AppIcon` set (all macOS sizes, 16–1024 @1x/@2x), wired via `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`.
- Artwork: the same blue cat `PetCharacterView` draws, centred on a cream (`#FBF8F1`) rounded-square tile following Apple's macOS icon grid (824/1024 body, ~185px corner radius, subtle shadow).
- Generated by a committed script (`scripts/make-icon.swift`) that renders the cat and writes the PNGs; the PNGs are committed so builds don't depend on the script. Replacing the PNGs later with a designed icon needs no code change.

## 4. Release build and DMG

- `scripts/make-dmg.sh <version>`:
  - Builds Release, universal (`ARCHS="arm64 x86_64"`, `ONLY_ACTIVE_ARCH=NO`), ad-hoc signed (`CODE_SIGN_IDENTITY=-`), with `MARKETING_VERSION=<version>` and `CURRENT_PROJECT_VERSION` from `$GITHUB_RUN_NUMBER` (fallback `1` locally).
  - Verifies both architectures with `lipo -archs` and the signature with `codesign --verify`.
  - Packages `PetChat-<version>.dmg` (UDZO) containing `PetChat.app` (shown as "Pet Chat") and an `Applications` symlink. No background image.
  - Runs locally on any Mac with Xcode.
- `.github/workflows/release.yml`: on push of tags `v*`, on a `macos-latest` runner: run unit tests, run `scripts/make-dmg.sh ${tag#v}`, then create a **draft** GitHub Release for the tag with generated release notes and the DMG attached (`gh release create --draft --generate-notes`).
- Version comes only from the tag; no version is stored in the project. First release: `v0.1.0`.

## 5. README

- Top "Install" section for normal users: download the DMG from Releases → drag Pet Chat to Applications → open it → one-time **System Settings → Privacy & Security → Open Anyway** (numbered steps, macOS 15 wording).
- Updating: download the new DMG and replace the app. ChatGPT users may see a one-time keychain prompt after updating; click **Always Allow**.
- Move the `xcodebuild` commands to a "Build from source" section; document `scripts/make-dmg.sh` and how to cut a release (push a `v*` tag, publish the draft).
- Fix stale lines: "Command + Return" → "Return" (Shift+Return for a new line); drop "There is no Dock icon"; mention the Show in Dock setting.

## Known limitations (accepted)

- Unsigned app: first launch needs Open Anyway; every update may trigger one keychain prompt for ChatGPT users.
- No auto-update; users must check Releases.
